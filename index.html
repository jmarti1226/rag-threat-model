The Problem

The most common enterprise AI pattern today is Retrieval-Augmented Generation (RAG): a company connects an off-the-shelf language model to a proprietary document store and lets employees query it through a chat interface. It requires no model training, produces grounded answers, and can be deployed in days.


The problem is the speed. Companies chase the trend and look for the quickest route to productivity gains, but rarely conduct the same architectural security review they would apply to any other new system. The result is a growing class of AI deployments that are functionally capable but architecturally unexamined.


Current security practice for AI is reactive — controls are applied after incidents, not before deployment. Traditional frameworks like STRIDE were not built for AI-specific threats. MITRE ATLAS catalogs real-world AI attacks but does not prescribe how to apply them to a specific system. No existing standard combines both into a deployable process for RAG architectures.

Reference Architecture

The system modeled is a corporate AI assistant with two pipelines: a real-time query pipeline and a document ingestion pipeline. Four trust boundaries define where data crosses between zones of different privilege.

The Critical Attack Chain

The biggest vulnerability is not the AI model — it is the documents you feed it. This five-step chain bypasses every UI-layer and query-layer control entirely.

T-C7-T1
Document Poisoning Attacker uploads a legitimate-looking document with a hidden prompt injection payload
↓
T-C5-T1
RAG Poisoning The malicious content is ingested, embedded, and stored silently in the vector database
↓
T-C3-T1
Indirect Prompt Injection A legitimate employee query retrieves the poisoned chunk, which now sits inside the AI's context window
↓
T-C3-E1
Privilege Escalation The injected payload overrides the system prompt, instructing the AI to act with elevated authority
↓
Sensitive data disclosed — no alerts, no error messages, no indication anything is wrong
Key insight: An organization that hardens the system prompt and deploys output filtering but neglects ingestion-layer controls has secured the wrong layer. The attack never touches the chat interface.
